## Project and commands

This is a TanStack Start + React + TypeScript app generated from the Lovable TanStack Start template. `package-lock.json` is present, so use `npm install` unless intentionally switching to Bun.

Common commands:

```bash
npm run dev          # Start Vite/TanStack Start dev server
npm run build        # Production build
npm run build:dev    # Development-mode build
npm run preview      # Preview built app
npm run lint         # ESLint over .
npm run format       # Prettier write over .
GITHUB_ACTIONS=true BASE_PATH=/ppt-to-sparkle-25/ npm run build  # Static build for GitHub Pages /ppt-to-sparkle-25/
```

No test runner or test files are currently configured in the repository, so there is no single-test command yet. Use `npm run lint` and `npm run build` for validation until tests are added.

## Architecture

- `vite.config.ts` delegates most setup to `@lovable.dev/vite-tanstack-config`. Do not manually add TanStack Start, React, Tailwind, tsconfig paths, Nitro, component tagger, env injection, alias, or dedupe plugins there; the config comment says duplicates can break the app.
- GitHub Pages deployment is handled by `.github/workflows/pages.yml`: it prerenders the TanStack Start app into `dist/client/index.html`, uploads that static folder, and deploys with GitHub Pages Actions. Set `GITHUB_ACTIONS=true BASE_PATH=/ppt-to-sparkle-25/` for local GitHub Pages-style builds on Windows/Git Bash.
- `src/server.ts` is the SSR entry wrapper. It imports TanStack Start's generated server entry, normalizes catastrophic h3 500 responses, and returns a generic HTML error page for caught SSR failures.
- `src/start.ts` creates the TanStack Start instance and registers request middleware for server-side error handling.
- `src/router.tsx` creates the TanStack Router with a per-router `QueryClient` in route context.
- `src/routes/__root.tsx` is the only root layout. It owns document metadata, imports `src/styles.css`, provides `QueryClientProvider`, and renders `<Outlet />`. Keep `<Outlet />` when editing the root.
- `src/routes/index.tsx` is the current app: a single landing page for STA\CUT with sections for recycling operations, technology, app flow, carbon trading, expansion, and goals.
- `src/routes/routeTree.gen.ts` is generated by TanStack Router. Do not edit it by hand.
- `src/routes/README.md` documents file-based routing conventions: `index.tsx` maps to `/`, `$id.tsx` is dynamic, `{-$category}.tsx` is optional, `$.tsx` is splat, `_layout.tsx` is a layout route, and `__root.tsx` is the app shell.
- `src/components/ui/*` contains shadcn/ui components. Add UI through these components or `components.json` aliases rather than recreating the same primitives elsewhere.
- `src/styles.css` is the Tailwind v4 design system. Semantic colors are CSS variables mapped in `@theme inline`; new colors must be added to both `:root` and `.dark` and registered in `@theme inline`.
- `src/lib/utils.ts` exports `cn()` for combining `clsx` and Tailwind class merging.
- Server/client boundary:
  - Files ending in `.server.ts`, such as `src/lib/config.server.ts`, are server-only.
  - On Cloudflare Workers, read `process.env` inside functions or handlers, not at module scope.
  - `import.meta.env.VITE_*` is public and ships to the browser; never put secrets there.
  - ESLint rejects imports from `server-only`; use `.server.ts` or TanStack Start server-only annotations instead.
- Error handling/reporting:
  - `src/lib/error-capture.ts` captures original client/SSR errors so `src/server.ts` can render the generic error page with better logging.
  - `src/lib/lovable-error-reporting.ts` reports client React error-boundary errors to Lovable when available.
